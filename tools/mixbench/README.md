# mixbench — стенд прослушивания «Умных переходов»

Офлайн-рендер переходов A → B тем же кодом движка, что в приложении (анализ, план, вариспид,
смена басов, микшер кроссфейда), без звуковой карты. Для каждой пары из `tracks.json` пишутся
два WAV (умный переход и обычный кроссфейд 6 с) и страница `out/index.html` с плеерами.

`music/` и `out/` в `.gitignore`: музыка и клипы остаются только локально.

## Команды (из корня репозитория)

Скачать музыку (уже скачанное пропускается, `-Force` — заново):

```powershell
pwsh tools/mixbench/fetch-music.ps1
```

Проанализировать треки и отрендерить все пары:

```powershell
$env:CARGO_BUILD_JOBS=3; cargo run -p mixbench --profile mixbench
```

Потом открыть `tools/mixbench/out/index.html` в браузере. Ключи: `--pre 20` / `--post 15`
(секунд до и после перехода), `--xfade 6` (длина обычного кроссфейда), `--only N` (одна пара).

## Как устроено

- `tracks.json` — треки (источник, лицензия, ожидаемый BPM) и пары. Новый трек: добавить
  запись, запустить `fetch-music.ps1`. `music/SOURCES.md` — список источников и лицензий,
  его пишет тот же скрипт.
- `mixtape-audio` с фичей `bench` (приложение её не включает) даёт
  `bench::render_transition` — тот же `State` движка, что в тестах, с отключённым устройством
  вывода — и `analysis::tempo_detail_file` (сетка долей и её устойчивость до порогов).
- Профиль `mixbench` — release без LTO, собирается за минуту.
- Проверки без прослушивания: детектированный BPM против ожидаемого (половинный/двойной темп),
  периодичность и сила доли (пороги 0.1 и 1.6), пик и RMS клипа, тишина и провалы громкости
  в самом переходе (±¼ с) по окнам 50 мс.

## Время анализа

`analyze_file` на одно ядро (профиль `mixbench`, 2026-10-19): 0.3–0.6 с на трек 2.5–5 мин,
~0.9 с на 7-минутный; рендер одного клипа (~45 с звука) — 70–100 мс. Весь прогон 16 треков
и 13 пар — ~25 с (вместе с замером громкости).
