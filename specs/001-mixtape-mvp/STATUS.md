## Готово

- **Phase 1–2 (каркас):** cargo workspace (`crates/{core,library,artwork,yt,audio,player,sync,win}` +
  `src-tauri` + `ui`), SQLite со схемой v1 и trigram-поиском (2–11 мс на 20k), обложки
  64/300/1024 + палитра, протокол `cover://`, окно без рамки с snap layouts.
- **US1 (локальный плеер) — сделан целиком, кроме замера T022:**
  - `crates/audio`: свой движок symphonia + libopus + cpal, gapless, точный seek, громкость
    EBU R128, смена устройства, **кроссфейд** (авто + короткий при ручном переключении,
    треки одного альбома остаются gapless).
  - `crates/player`: очередь (play next / add / shuffle с восстановлением / repeat), `Player`
    (gapless-преемник, пропуск ошибок, play stats, снимок очереди в БД).
  - `crates/win`: SMTC (медиаоверлей, медиаклавиши) + кнопки на миниатюре.
  - UI: главная, библиотека, альбом/исполнитель/плейлист, поиск, настройки, мини-плеер,
    полноэкранный плеер, очередь (боковая и «шторка» в полноэкранном), горячие клавиши + «?».
  - Dev-импорт папки (Настройки → Библиотека → «Выбрать папку…»), обложка = картинка рядом.
- Иконка: «Бургунди 3» (эквалайзер, `assets/logo.svg`).
- **US2 (выкачка из YouTube Music) — сделан и проверен вживую:** вход через окно Google
  работает, синк плейлиста лайков скачивается целиком (недоступные на YouTube треки пропускаются).
  - `crates/yt`: cookies (Netscape / EditThisCookie JSON) + SAPISIDHASH, свой InnerTube-клиент
    вместо RustyPipe (лайки, плейлисты, альбомы, подписки, страницы альбома/плейлиста/артиста,
    один трек через `next`), `StreamResolver` (yt-dlp пачками по 5, кэш URL), `Pacer`
    (≤2 параллельно, 1–3 с, backoff), обложки `=w1200-h1200`. Живая проверка: `cargo run -p
    mixtape-yt --example probe -- .secrets/cookies.txt`.
  - `crates/sync`: `sources` (синк + импорт по ссылке), `downloader` (воркеры, докачка `.part`,
    повторное разрешение URL на 403, пауза, место на диске), `fetch`, `disk`, `url_import`.
    Сквозная проверка во временной папке: `cargo run -p mixtape-sync --example e2e --
    .secrets/cookies.txt src-tauri/binaries <ссылка>`.
  - `crates/library`: `jobs` (download_jobs), `ytm` (зеркала плейлистов, лайки из YTM).
  - `crates/win::dpapi`: cookies хранятся в `%LOCALAPPDATA%\Mixtape\account.bin` под DPAPI.
  - Вход: окно Google внутри приложения (инкогнито WebView2, `login_window.rs`) — cookies
    забираются сами; запасной путь — вставка cookies.
  - UI: экран «Загрузки», модалка подключения, «Добавить по ссылке» (Ctrl+L / Ctrl+V со
    ссылкой), кольцо прогресса в сайдбаре. В браузере: `http://localhost:5173/?mock`.
  - Фото исполнителей: качаются при открытии страницы, после синка и при старте; палитра
    фото хранится (миграция 002) — шапка страницы исполнителя в его цветах.
  - При старте: тестовые локальные импорты (`local…`) сливаются с YTM-двойниками
    (`ytm::merge_local_twins`), имена без id привязываются к исполнителям
    (`ytm::link_artists_by_name`, иначе создаётся `localart…`).
  - Ссылка на исполнителя в «Добавить по ссылке» ставит в загрузки всю дискографию;
    синк повторяется сам раз в 12 ч с последним выбранным набором источников (`sync_plan`).
  - Не сделано: замена клипа на аудио-версию (часть лайков — клипы без альбома;
    нужна колонка «источник аудио» в tracks).

- **US5 (тексты) — сделан:** `crates/sync::lyrics` (lrclib `/api/get` → `/api/search` ±2 с,
  парсер LRC, кэш `lyrics_cache`, «не найдено» перепроверяется через 7 дней), команда
  `lyrics_get`, `LyricsPanel.svelte` в полноэкранном плеере (кнопка в мини-плеере открывает
  полноэкранный с текстом, клавиша T). Живая проверка: `cargo run -p mixtape-sync --example
  lyrics -- "a-ha" "Take On Me" "Hunting High and Low" 225`.

- **US3 («Включить микс») — сделан, звук проверяет пользователь:**
  - `crates/yt::radio` (`next` RDAMVM, чипы без «Сохранить», продолжение, `radio_playlist`,
    `set_like`); `crates/player::mix` (`MixSession`: дедупликация, подгрузка при ≤5,
    чип заменяет будущую часть, поколения против устаревших ответов); `Player` играет треки
    без файла через `StreamProvider` (откладывает загрузку восстановленного трека до Play,
    подхватывает следующий, когда стрим готов).
  - Стрим: `crates/audio::sparse` (`SparseCacheFile`, неблокирующее чтение в движке,
    Buffering), `crates/sync::stream` (`StreamFill`, докачка от позиции чтения, 403 → новый
    URL), `src-tauri/src/streaming.rs` (`AppStreams`: резолв, кэш `cache/`, громкость, LRU,
    предзагрузка: URL на 5 вперёд, файлы на 2 вперёд).
  - **googlevideo + заголовок Range вместе дают 416** для любого куска не с нуля —
    googlevideo получает только параметр `range=` (`fetch::ranged`); это чинит и загрузки
    библиотеки длиннее 10 МБ.
  - Кэш и автосохранение: `library::cache_lru` (лимит 5 ГБ, LRU, перенос в библиотеку без
    повторной загрузки после 3 полных прослушиваний / лайка / «Скачать»; загрузчик
    библиотеки тоже сначала берёт файл из кэша); лайки в YTM через
    `like_outbox` (`sync::likes`, отправка сразу, при старте, раз в 5 мин и при возврате сети).
  - Офлайн: тост «Нет связи — микс не продолжается» с «Продолжить из библиотеки»
    (`mix_continue_local`: сначала те же исполнители). Настройка «Включать полноэкранный
    режим после включения микса». Правый клик по всей нижней панели — меню трека.
  - Живые проверки без звука: `cargo run -p mixtape-sync --example mix_e2e --
    .secrets/cookies.txt src-tauri/binaries <videoId>`.
- **US4 (каталог) — сделан:** `crates/yt::search` (все виды, фильтры, продолжение, подсказки),
  `crates/sync::catalog` (альбомы/артисты/плейлисты из каталога как `remote`, обложки по 6),
  `commands/catalog.rs`; поиск: вкладки «Библиотека» / «YouTube Music»; страницы альбома,
  исполнителя («Популярное в YouTube Music», «Дискография») и плейлиста берут недостающее

  плейлист / дискографию»; `play` для альбома/плейлиста/исполнителя из каталога сначала
  подтягивает треки. Проверка: `cargo run -p mixtape-sync --example catalog_e2e --
  .secrets/cookies.txt "daft punk"`.
- **Главная (T085–T087):** локальные разделы сразу, ниже шелфы YTM (`home_shelves`, кэш 30 мин,
  скрыты без сети/аккаунта), карточки миксов запускают `mix_start_playlist`.
- **Polish:** настройки «Хранилище» (лимит кэша, автосохранение N×, очистка, папка данных),
  статус сети `net:status` (`src-tauri/src/net.rs`), анимации только transform,
  NSIS-инсталлятор `target/release/bundle/nsis/Mixtape_0.1.0_x64-setup.exe` (~50 МБ).
- **Бюджеты** (quickstart.md → «Результаты»): старт 0,46–0,76 с на 20k (было 1,75 с — проверка
  целостности теперь листает папки), RAM 109–111 МБ в простое, поиск ≤ 9 мс. Синтетическая
  библиотека: `--example synth_library`, запуск с `MIXTAPE_DATA_DIR`. Релизный бинарь без
  инсталлятора: `cargo build --release -p mixtape --features tauri/custom-protocol`.
- **Импорт из Spotify:** ссылка на плейлист/альбом (или список «Исполнитель — Название») в
  «Добавить по ссылке» → локальный плейлист из песен YouTube Music (`remote`, ничего не
  качается до «Скачать плейлист»). `crates/sync::spotify`: embed-страница без логина (≤100
  треков), остальное — `pathfinder fetchPlaylist` с анонимным токеном embed (хеш запроса может
  смениться — тогда плейлист режется, сводка это пишет); поиск Songs, ≤3 параллельно,
  оценка по названию/исполнителям/длительности ±3 с. Команды `spotify_import/cancel/download`,
  событие `spotify:progress`. Живая проверка без БД: `cargo run -p mixtape-sync --example
  spotify_match -- .secrets/cookies.txt <ссылка | файл со строками> [лимит]`.

- **SoundCloud и Bandcamp в «Добавить по ссылке» (2026-10-19):** без аккаунта, через тот же
  yt-dlp, без ffmpeg и без фоновой работы вне импорта. Ссылки: SC трек / сет / профиль
  (`/<user>`, `/<user>/tracks`, до 100 последних треков), BC `*.bandcamp.com/track|album/…`
  (`url_import::parse_external`, зеркало в UI — `parseExternalUrl` в `ipc/sync.ts`).
  `crates/sync::external`: `yt-dlp -J --flat-playlist` → треки по одному (`-f FORMATS`, без
  перекодирования) прямо в `library/<id>.<ext>`; id `sc`/`bc` + md5 id сайта (повторный импорт
  ничего не качает), BC-альбом → альбом, SC-сет → локальный плейлист (повторно — тот же),
  сет-альбом/EP → ещё и альбом; «Исполнитель - Название» в SC делится. Go+ превью (30 с)
  отклоняются. Прогресс — строка синка на экране «Загрузки» (`SyncStatus.import`), итог — тост.
  Попутно: symphonia `mp3`; склеенные HLS-сегменты SC (`sidx` на каждый сегмент) чинит
  `mixtape_audio::drop_segment_indexes` (иначе играли бы первые 10 с); миграция 008 разрешает
  `container` mp3/ogg. Живая проверка без БД приложения и без звука: `cargo run -p mixtape-sync
  --example external_e2e -- src-tauri/binaries/yt-dlp-x86_64-pc-windows-msvc.exe <папка> <ссылка> [лимит]`.

## Дизайн-решения пользователя (соблюдать)

- Интерфейс 1:1 как у Liner: чёрное окно, отдельные скруглённые панели `#0a0a0a` с отступом
  8 px, радиус 10 px, монохром (акцент — белый), цвет только от обложки (`--glow`).
- Сайдбар: логотип (→ главная), иконки Solar Bold 28 px без подложек, настройки внизу,
  у активной вкладки нет анимации нажатия. Логотип без обводки.
- Нижний плеер: на всю ширину справа от сайдбара; вся панель — таймлайн (заливка + seek
  кликом/протяжкой по пустому месту); по центру только ⏮ ▶ ⏭; остальное — капсула справа.
  Клик по названию/обложке → полноэкранный плеер.
- «Назад» (⏮) всегда предыдущий трек, никогда не перематывает в начало.
- Полноэкранный плеер: компактная колонка по центру, фон из размытой мини-обложки
  (blur 12 px — не сильнее), тексты по кнопке сдвигают колонку влево.
- Очередь: один список, играющий подсвечен; плавное перетаскивание pointer-событиями;
  бросок на играющий трек = играть его вместо; в полноэкранном — карточки без общей
  подложки, плеер за ними размыт фильтром (НЕ backdrop-filter — ломает WebView2),
  закрытие кликом по пустому месту с защитой от случайных нажатий.
- Анимации — только пружины (motion.dev, `ui/src/lib/motion.ts`), без масштабирования
  при наведении; кастомные тултипы (`data-tip`), курсор pointer на всём кликабельном.
- Двойной клик разворачивает окно только по верхней полосе 44 px.
- Колёсико мыши работает на всех ползунках (громкость 5 %, таймлайн 5 с).
- Полноэкранный плеер: в правом нижнем углу обложки — лайк (с 2026-10-19, вместо «+»), меню трека —
  правый клик по обложке («⋯» убран); ряд под кнопками: громкость, текст, очередь — так и оставить
  (симметричные варианты пользователь отверг). Переключение текста — колонка едет
  transform'ом, панель текста выезжает справа. Любой переход по `router.go` закрывает его.
- **Производительность (ревью 2026-10-17):** никаких постоянных rAF-циклов и бесконечных
  CSS-анимаций — прогресс через `followProgress()` (`player.svelte.ts`), видимость через
  `lib/stores/visible.svelte.ts`, фон полноэкранного плеера — `CoverBackdrop.svelte`
  (canvas 10 fps, стоит на паузе). Ядро шлёт позицию раз в ~5 с + при каждом событии,
  UI экстраполирует. Аудиоустройство закрывается на паузе (50 мс → suspend, 30 с → close),
  очередь пишется в БД только при изменениях. yt-dlp — пачками с дедупликацией.
  Агентам собирать Rust с `CARGO_BUILD_JOBS=3` — иначе у пользователя лагает весь ПК.
- Полосок спектра в полноэкранном плеере не нужно (пользователь убрал); спектр удалён и из
  ядра (`spectrum_subscribe` больше нет).
- Экономия батареи: устройство вывода открывается только на Play (восстановленный на паузе
  трек его не открывает), на паузе/стопе поток cpal приостанавливается через 50 мс и
  закрывается через 30 с; поток движка при игре просыпается ≤ 10 раз/с, на паузе спит до
  команды. Состояние в UI — на изменениях и раз в ~5 с; очередь пишется в БД только при
  изменении (`queue_snapshot`), позиция и громкость — раз в 20 с и на паузе/выходе
  (`playback_pos`).
- Горячие клавиши по `e.code` (любая раскладка), список по «?» (`ui/src/lib/stores/hotkeys.ts`).
- Vite HMR иногда оставляет старые модули (адреса с `?t=`): если правка «не видна» —
  перезапустить приложение целиком.
- Размеры в UI, которые должны быть точными, задавать в px: корневой шрифт 14 px, rem меньше.
- Трек в списках и очереди включается одним кликом (не двойным).
- Страницы-формы (Настройки, Загрузки) — колонка по центру панели, а не прижатая влево.
- Нижняя панель: нажатие в пустое место сразу перематывает, протяжка — скраб с пузырьком
  времени. Ползунок громкости в капсуле открывается с задержкой 300 мс (hover intent).
- Имена исполнителей кликабельны везде (`ArtistLinks.svelte`); у карточек альбомов/
  исполнителей/плейлистов своё контекстное меню (`collectionMenu.ts`), системное меню
  WebView отключено (кроме полей ввода).
- «Назад/вперёд» — стрелки в строке кнопок окна (слева от «—»), плюс Alt+←/→ и боковые
  кнопки мыши; назад восстанавливает прокрутку.
- Ленты на главной и чипы тянутся мышью (`dragScroll`), с инерцией.
- Модалки и контекстное меню без масштаба и без анимации прозрачности поверх
  backdrop-filter: в WebView2 это даёт мутный текст/мигание (`rise`, `blurIn` в motion.ts).
- Первые анимации (2026-10-19): первый `backdrop-filter` и первый рисунок с filter/blend на GPU-canvas
  подвешивают GPU WebView2 на 50–200 мс, и переход «проскакивает». Поэтому canvas фона полноэкранного
  плеера рисуются на CPU (`willReadFrequently`), а `warmUpCompositor()` (motion.ts) один раз при показе
  окна рисует невидимый слой с blur. Проверять замером кадров в Edge через playwright-core на `?mock&scene=home`.
- Мини-плеер — фиксированно 380×116, окно не растягивается; в углу shuffle / repeat / громкость (`Volume popout`).
- Вход в YouTube Music — только окно внутри приложения: браузер по умолчанию сессию
  не вернёт (OAuth для YTM нет, cookies Edge/Chrome зашифрованы и общие с браузером).

- Языки: English, Українська, Русский (порядок в списке именно такой). Строки UI — только через `t` из `$lib/i18n` (словари `ui/src/lib/i18n/{en,uk,ru}/{base,screens,ui}.ts`, en — эталон формы); сообщения ядра — `mixtape_core::tr` / `trf!`. YouTube отвечает на языке приложения (`hl`), парсеры обязаны понимать en/uk/ru.
- Скриншоты для README — только из демо-мока (`?mock&lang=..&scene=..`), никогда из реальной библиотеки.

- Релиз: поднять версию в `src-tauri/tauri.conf.json` и `Cargo.toml`, затем `./scripts/release.ps1 -Notes <файл>` — сборка без ключа, потом подпись установщика (`tauri signer sign`, пароль ключа из `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` или запросом) + `latest.json` в GitHub Releases. Ключ подписи обновлений — `.secrets/tauri-updater.key` (не в git, нужна резервная копия: без него установленные копии не примут новые версии). Обычному `pnpm tauri build` ключ не нужен.
- Безопасность (2026-10-19): yt-dlp всегда через `resolver::ytdlp_command` (`--ignore-config --no-plugin-dirs`, рабочая папка — tmp приложения, `--` перед ссылками, дерево процессов убивается и при отмене); ссылки из JSON yt-dlp проверяются (`external::safe_url`); `TrackId` из внешних данных — только `[A-Za-z0-9_-]{1,64}`; обложки — только https с известных CDN (`thumbs::is_allowed`), тела ответов ограничены (`innertube::read_limited`), декодер обложек с лимитами; окно входа ходит только по Google/YouTube; ACL Tauri: новые команды добавлять в `COMMANDS` в `src-tauri/build.rs` и в capability (`capabilities/default.json` — главное окно, `tray-menu.json` — меню трея); `dev_import_folder` только в debug-сборке.

- Окно: window-state НЕ сохраняет/восстанавливает видимость (иначе мигание при скрытом автозапуске); мини-плеер — тот же главный webview в компактном режиме (второе окно не создаём ради памяти); оверлей snap-layouts плагина frame в мини-режиме скрыт. Автозапуск хранится только в реестре (HKCU Run), не в Prefs.
- Меню значка в трее — своё, не системное: отдельное маленькое окно `tray-menu` (прозрачное, без рамки, поверх всех, без кнопки на панели задач) со страницей `ui/tray-menu.html` (свой вход Vite, не грузит приложение). Создаётся при первом правом клике, между открытиями скрыто, через 2 мин простоя закрывается (WM_CLOSE — плагин frame снимает свой snap-оверлей). ## Как запускать

- Приложение: `pnpm tauri dev --no-watch` из корня (без слежения за Rust, чтобы пересборки
  не закрывали окно). После правок Rust — остановить `mixtape.exe` и запустить заново.
  UI обновляется на лету (Vite HMR); если «залип» — `touch ui/src/main.ts` или Ctrl+R.
- Тесты: `cargo test --workspace`, `cargo clippy --workspace --all-targets -- -D warnings`, `pnpm -C ui check`.
- `.cargo/config.toml` задаёт `TS_RS_EXPORT_DIR` (TS-типы из Rust); cmake для libopus — из `PATH` или
  переменной `CMAKE` (в репозитории пути нет, см. README).
- Репозиторий: https://github.com/Reva1v/mixtape (ветка main, пушить после коммитов по просьбе).
- Секреты: `.secrets/cookies.txt` (cookies YouTube Music для живых проверок, в .gitignore).
- yt-dlp и deno — `src-tauri/binaries/` (скрипт `scripts/fetch-sidecars.ps1`: версии
  зафиксированы, SHA-256 проверяется).
- Не воспроизводить звук самому и не давать агентам открывать аудиоустройство — пользователь
  в наушниках.
